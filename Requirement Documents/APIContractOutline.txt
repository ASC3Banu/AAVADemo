INTRODUCTION
================================================================================

This document outlines the API contracts for the AI-Powered Logistics Monitoring System.

API Design Principles:
- RESTful design following OpenAPI 3.0 specification
- Resource-oriented URLs
- Standard HTTP methods (GET, POST, PUT, PATCH, DELETE)
- JSON request and response bodies
- Consistent error handling
- Versioned APIs with backward compatibility

Authentication:
- OAuth 2.0 with JWT tokens
- API Key authentication for service accounts
- Token expiration: 15 minutes (access), 7 days (refresh)

Rate Limiting:
- Standard tier: 1,000 requests per hour
- Premium tier: 10,000 requests per hour
- Enterprise tier: 100,000 requests per hour

================================================================================
1. AUTHENTICATION APIs
================================================================================

1.1 User Authentication
Endpoint: /auth/login
Method: POST
Description: Authenticate user and obtain access token
Authentication Required: No
Rate Limiting: 10 requests per minute per IP

Request Schema:
{
  "email": "string (required)",
  "password": "string (required)",
  "mfa_code": "string (optional)"
}

Response Schema (200 OK):
{
  "access_token": "string",
  "refresh_token": "string",
  "token_type": "Bearer",
  "expires_in": 900,
  "user": {
    "id": "string",
    "email": "string",
    "name": "string",
    "roles": ["string"]
  }
}

Error Codes: 400, 401, 403, 429, 500

1.2 Token Refresh
Endpoint: /auth/refresh
Method: POST
Description: Refresh access token
Authentication Required: Yes
Rate Limiting: Standard

Request Schema:
{
  "refresh_token": "string (required)"
}

Response Schema (200 OK):
{
  "access_token": "string",
  "token_type": "Bearer",
  "expires_in": 900
}

Error Codes: 400, 401, 500

2. SHIPMENT TRACKING APIs
================================================================================

2.1 Create Shipment
Endpoint: /shipments
Method: POST
Description: Create a new shipment record
Authentication Required: Yes
Rate Limiting: Standard

Request Schema:
{
  "tracking_number": "string (optional)",
  "origin": {
    "address": "string (required)",
    "city": "string (required)",
    "country": "string (required)",
    "postal_code": "string (required)"
  },
  "destination": {
    "address": "string (required)",
    "city": "string (required)",
    "country": "string (required)",
    "postal_code": "string (required)"
  },
  "carrier_id": "string (required)",
  "service_type": "string (required)",
  "package_details": {
    "weight": "number (required)",
    "dimensions": {
      "length": "number",
      "width": "number",
      "height": "number"
    }
  }
}

Response Schema (201 Created):
{
  "id": "string",
  "tracking_number": "string",
  "status": "string",
  "created_at": "string",
  "_links": {
    "self": "string",
    "tracking": "string"
  }
}

Error Codes: 400, 401, 403, 409, 422, 500

2.2 Get Shipment
Endpoint: /shipments/{shipment_id}
Method: GET
Description: Retrieve shipment details
Authentication Required: Yes
Rate Limiting: Standard

Response Schema (200 OK):
{
  "id": "string",
  "tracking_number": "string",
  "status": "string",
  "current_location": {},
  "origin": {},
  "destination": {},
  "carrier": {},
  "events": []
}

Error Codes: 400, 401, 403, 404, 500

2.3 List Shipments
Endpoint: /shipments
Method: GET
Description: List shipments with pagination
Authentication Required: Yes
Rate Limiting: Standard

Query Parameters:
- page: integer (default: 1)
- page_size: integer (default: 20, max: 100)
- status: string
- carrier_id: string

Response Schema (200 OK):
{
  "data": [],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total_pages": 10,
    "total_items": 200
  }
}

Error Codes: 400, 401, 403, 500

6. COMMON ERROR RESPONSE FORMAT
================================================================================

All error responses follow this format:

{
  "error": {
    "code": "string (error code)",
    "message": "string (human-readable message)",
    "details": [
      {
        "field": "string",
        "issue": "string"
      }
    ],
    "request_id": "string (UUID)",
    "timestamp": "string (ISO 8601)"
  }
}

================================================================================
7. RATE LIMITING HEADERS
================================================================================

All responses include rate limiting headers:

- X-RateLimit-Limit: Maximum requests per window
- X-RateLimit-Remaining: Remaining requests in current window
- X-RateLimit-Reset: Timestamp when limit resets
- Retry-After: Seconds to wait (included in 429 responses)

================================================================================
8. VERSIONING AND DEPRECATION
================================================================================

API Versioning:
- Version included in URL path (/v1/, /v2/)
- Backward compatibility maintained for minimum 12 months
- Deprecation notices provided 6 months in advance
- Sunset header included in deprecated endpoint responses

Deprecation Header Example:
Sunset: Sat, 31 Dec 2024 23:59:59 GMT
Link: <https://api.example.com/v2/endpoint>; rel="successor-version"
